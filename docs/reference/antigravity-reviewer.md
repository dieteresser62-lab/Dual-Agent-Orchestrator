# Antigravity reviewer candidate

Status: **candidate, blocked until Slice 6**. The Phase-0 gate is `positive_with_finding`, not a selection or production approval. The default reviewer remains Claude. The planned scope is private WSL 2 / Ubuntu / ext4 use with the operator's fixed Google subscription.

The v2 [capability register](../../schemas/native-provider-schema-capabilities-v2.json) names the measured `antigravity` writer profile and binds its CLI version exactly to 1.2.12. Its reviewer and final reviewer [slot entries](../../schemas/role-provider-certifications-v1.json) are separate candidates, with no implementer entry. Candidate status denies normal starts and resumes; changing only the table status cannot promote it before the Slice-6 qualification and canary evidence contract exists. The entries bind manufacturer `google` to the `gemini-` model family; the CLI also advertises Claude and GPT-OSS models, which are excluded by this rule. Model and effort remain outside transport equivalence, as for Codex and Claude. The profile's [capability evidence](../evidence/antigravity/capability-v1.json) records the six s6 writer digests and the rejected positional tuple probe. The adapter and provider start belong to Slice 3.

The proven probe used AGY 1.2.12 with the requested `gemini-3.1-pro-high` model, an isolated HOME, freshly written `request-review` settings, an exact deny list, a per-run read allowance, and a read-only `dao-reviewer` agent. Its cwd was a container under `/var/tmp/dao-agy-p0`, with the repository snapshot in `repo/` and request, evidence and schema files in `input/`. The agent disabled inherited customizations and MCP, subagents, and command execution. Slice 4 binds this measured native mechanism to every review attempt. No external wrapper or host installation is used. The [integration evidence](../evidence/antigravity/isolation-v1.json) maps each Phase-0 protection control to the implementation and provider-free checks. No real AGY start is admitted while both slot entries remain candidates.

The isolated HOME and run root are profile-bound options in `orchestrator.toml`:

```toml
[agent_profiles.agy]
provider = "antigravity"
model = "gemini-3.1-pro-high"
effort = "high"

[agent_profiles.agy.provider_options.antigravity]
home = "/home/operator/.dao-antigravity-reviewer"
run_root = "/var/tmp/dao-agy-review-1000"
```

When omitted, the defaults are `~/.dao-antigravity-reviewer` and `/var/tmp/dao-agy-review-<uid>`; these are normalized to absolute paths and bound by digest to the run profile. A HOME change on resume is rejected. The HOME must differ from the personal HOME and remain outside the reviewed repository. The run root must be private, below `/var/tmp`, and disjoint from the repository. A private isolated HOME is chosen because the measured `/home` read deny covers its configuration and OAuth file; a distinct run base under `/var/tmp` is needed for the sole `read_file(<run base>)` allowance. AGY's own cache stays under the isolated HOME. The adapter rejects a missing, symlinked or non-0600 `.gemini/antigravity-cli/antigravity-oauth-token` without reading it. For the one-time interactive login, from a disposable directory run `env -i HOME=<isolated-home> PATH=/usr/local/bin:/usr/bin:/bin LANG=C.UTF-8 TERM=xterm-256color AGY_CLI_DISABLE_AUTO_UPDATE=true <agy-binary>`; do not trust the login workspace or issue a review prompt there.

Each attempt takes an exclusive, bounded per-HOME lock before atomically replacing `settings.json` and `dao-reviewer/agent.md`; existing hardlinks cannot redirect those writes. It then copies the repository to a new `repo/` snapshot, writes the bound request, evidence and schema into `input/`, and seals files to 0444 and directories to 0555 before the provider process starts. The cwd is the container above both directories. The effective log line, normalized settings, byte-identical agent file and complete container contents and modes are checked after the process, before the review can be accepted. AGY may omit the default `toolPermission: request-review` field when normalizing settings; any `trustedWorkspaces` entry is rejected. The runtime log is kept outside the allowed run base and deleted after the check because it contains the account email. The lock covers this postcheck and cleanup; incomplete cleanup or a duration over 15 seconds rejects the review. A resumed attempt rebuilds the same boundary and Task-A binary identity checks run again before start. Version/help identity probes also use the isolated HOME and a neutral cwd, so they do not inspect personal or repository configuration.

The native rule was measured against shell, WSL launchers, Windows mounts, symlinks, traversal, outside reads, writes, hooks, MCP, browser and delegation attempts. Merely clearing WSL variables is not treated as protection: the runner forwards those variables when present. POSIX file modes add a tamper check but cannot stop the owning UID from changing modes; the AGY tool permissions carry the measured boundary. Missing tools, malformed settings or a changed effective log line cause a technical rejection, never approval. The two Slice-6 live canaries must test the integrated path before selection.

The adapter sends one `agy -p` turn with JSON output, the bound writer file, an explicit Gemini model and effort, `--sandbox`, `--disable-slash-commands`, `--agent dao-reviewer` and `--print-timeout <N>s`. Profile timeout `0` becomes `0s` and removes the runtime deadline; process-group termination still has a bounded cleanup path. The CLI receives null stdin and a fixed environment containing only the isolated HOME, fixed PATH/LANG/TERM, the disabled auto-update switch and explicitly forwarded WSL interoperability variables. Policy comes from the role-bound agent file. The provider input meter counts the actual request chunks, evidence, manifest, schema, agent policy and start directive. A configured `[[provider_input_budget]]` rule can select `provider = "antigravity"` for each reviewer operation.

Only a single strict stdout JSON object is accepted. The adapter checks exit code, `SUCCESS`, empty `error` and denials, an object `structured_output`, and a type-exact echo of the writer schema. It then requires the sole native result object and its bound request ID; the shared native runtime subsequently checks the full writer and domain contract. `response` prose is never used as a fallback. Stderr uses the narrow `agy-stderr-v1` classification; unknown diagnostics fail closed. Records carry only fixed diagnostic codes and CLI usage counters, never raw stderr, the AGY runtime log, or an invented served-model confirmation. The raw fixture corpus is [antigravity-envelopes-v1.json](../../tests/fixtures/antigravity-envelopes-v1.json).

The **complete review snapshot and input evidence are sent to Google** on each provider call. Operators must therefore treat the snapshot, request, evidence and schema as externally disclosed. The Phase-0 protection series did not measure the subscription quota, purchased credits or telemetry. CLI usage reports 2,115,470 total tokens across 34 AGY calls; this is not a billed-token or currency total. Protection calls typically took tens of seconds, while the final six format calls took roughly 97–146 seconds of CLI time and 63,306–89,796 total tokens each. The measured probe limit was 600 seconds plus at most 15 seconds cleanup; a later runtime timeout is derived from qualification measurements.

Known weaknesses: a soft permission denial can terminate a print-mode run with `SUCCESS` and no structured result; `status: ERROR` can still carry one. Strict mode prompted for workspace reads, and AGY normalized settings by removing keys. `manage_task` appeared in the tool surface despite being absent from the agent list. Symlink targets were resolved before read permission checks. In the final format case F6, the writer and domain checks passed, but the model chose `CONTRACT-UNCLEAR` instead of the expected `DISCOVERY_OUTPUT_LIMIT` when finding capacity was exceeded. Slice 5 must recheck capacity at 128 and 512 findings.

## Slice-5 qualification tool and evidence

The [v2 protocol](../evidence/antigravity/qualification-protocol-v2.json) remains `slim` and `experimental`; v1 is historical and rejected by the harness. The [series](../evidence/antigravity/qualification-series-v1.json), [sanitized envelopes](../evidence/antigravity/qualification-envelopes-v1.json), and [blind quality results](../evidence/antigravity/quality-results-v1.json) are pending measurement evidence. The operator granted a blanket corpus approval on 29 September 2026 without individual expert review. Executable hidden proofs and the steering reviewer's diff plausibility check form the documented basis. The v2 corpus digest binds this approval and the preregistered clean-case rules. A changed corpus is rejected.

`scripts/probe_reviewer.py prepare-case <transport|large_output|quality> <case-id> <fresh-directory>` creates the exact review source. Transport IDs are `F1:1` through `F6:2`; the two suffixes mean separate one-shot processes and distinct request IDs. The `print_timeout` call `T1` uses a separately prepared F2 transport source. Large IDs are `128` and `512`; quality IDs are `Q1` through `Q6`. The large fixture has one independently incorrect inclusive boundary per module. Its public import test is present; `--proof-out <absolute-path-outside-source>` writes the separate hidden proof and must never put it in the review source, request, or evidence. The harness checks the complete source digest before a provider start. It runs the public quality or large-fixture test with a fixed, provider-free Python command before building its bound request.

One call uses `scripts/probe_reviewer.py qualification-call <kind> <case-id> <agy|claude> --series-id <id> --call-id <id> --profile <profile.toml> --source-repo <case-directory> --output-dir <evidence-directory> --live`; optional `--quota-observation <json>` binds a separately observed subscription quota and `--tag <text>` records the day or operator batch without changing the profile digest. A TOML profile needs `live = true`, an absolute `binary`, a 40-character `commit_sha` matching the committed tool HEAD, `model`, `effort`, and optionally `timeout_seconds = 600`. AGY also needs `[provider_options.antigravity]` with isolated `home` and private `run_root`. AGY fixes `gemini-3.1-pro-high`/`high`; Claude fixes `opus`/`high` and uses its productive `--restricted` adapter. All ordinary qualification calls use the frozen 600-second probe limit; the single print-timeout case uses an explicitly smaller positive value. The 15-second cleanup bound remains in the adapter. The command bypasses candidate certification solely to measure the candidate through `NativeAntigravityReviewAdapter`; normal start and resume certification remain blocked. This command is an operator-only live opt-in and is not an orchestrator run.

The call builds `build_native_review_request` and the adapter's `build_reviewer_input`, seals the Slice-4 AGY workspace where applicable, and uses `run_native_review_agent` for process groups, input budget, response validation, and bound domain parsing. Its local append ledger records an intent and process start before the call. A recorded or uncertain call ID cannot be retried. Each result records provider, reviewer role, slot, case, request ID and digest, transmitted writer digest, source/profile/binary/commit digests, limit, UTC start, duration, status, denied actions, usage, quota, tag, and raw UTF-8 stdout bytes. Request and writer bytes accompany sanitized envelopes so failed historical series remain inspectable after a version change. The sanitizer replaces account-email and credential patterns before writing; operator inspection of all raw files is still required before promotion to versioned evidence. The CLI does not confirm which model was actually served; the model slug records the requested model only. Subscription quota and purchased-credit behavior remain unmeasured until the operator supplies evidence.

`evaluate-qualification <series.json> <envelopes.json> [--quality-results <quality.json>]` checks exact call order and count for each provider series, fresh request IDs, source/request/writer bindings, raw output against the writer and domain parser, and failed attempts. F6 keeps its known semantic failure if repeated. A restart requires `--restart-diagnosis <text>` and `--restart-change <text>` on the first call of a new full series, with a changed commit, profile, writer, or binary; old failed and incomplete attempts stay in the files. No individual retake or filtering is accepted. The print-timeout passes only when the stored AGY stderr is the versioned print-timeout shape, the call is technically rejected, and no result object is accepted. Auth, quota, network, denial, and malformed-output cases stay technical failures.

At 128 findings, `max_new_findings` is 129: the expected domain result is `final_review_completed` with 128 unique in-scope paths and IDs. At 512, the maximum capacity is 512: the writer must fully parse 512 distinct in-scope findings, after which the existing domain parser returns `DISCOVERY_OUTPUT_LIMIT`. The checker requires both the complete raw set and that precise stop. Silent truncation fails. This interprets the existing protocol's full-parsing rule without changing its counts or acceptance threshold. A proposed finite timeout appears only after successful measurements including 512: `ceil(1.5 × maximum successful seconds / 60) × 60`, with probe-limit censoring reported. It is a proposal, not a profile constraint; runtime value `0` remains allowed. No confirmation series is implied.

For blind quality review, `prepare-blind-inputs <series.json> <envelopes.json> <sources.json>` extracts exactly one valid result per provider and Q1–Q6. `blind <sources.json> <assessment.json> <separate-mapping.json> --seed 20260929` assigns neutral IDs. `export-rater-packets <assessment.json> <separate-mapping.json> <output-directory>` writes identical packets for the independent Codex and steering raters, with the [versioned rubric](../evidence/antigravity/quality-rubric-v1.json) and ground truth but without provider metadata. The secret mapping stays separate. `render-rater-prompt <codex-packet.json> <codex-prompt.txt>` assembles the exact Codex input from the packet and rubric. Each rater returns strict `quality-rating-v1` JSON with a reason per criterion. `combine-quality-ratings <packet.json> <mapping.json> <codex-rating.json> <steering-rating.json> <quality-results.json> --questions-out <questions.json>` records agreement and writes one everyday-language operator question per disputed rule-relevant criterion. The rule counts unsupported findings only in Q5/Q6, where every finding is unsupported by preregistration; a defect-case count dispute keeps the higher count without an operator question. An incomplete result never passes or reveals the mapping. Repeat the same command with `--operator-answers <answers.json>` after the operator answers each disputed question. Only then are the twelve final judgments frozen and the provider mapping revealed. The unchanged quality rule requires both critical defects, at least three of four defects, at most one unsupported finding across Q5/Q6, and no invented critical finding. Claude is scored separately. When AGY passes and Claude fails, the operator decides experimental selection after unblinding; record this with `--claude-special-decision approve_experimental|deny_experimental`.
